## O4 — Formulaire science (ordre cognitif)

1. **Quel problème de compréhension l'IT pose-t-il ?** → Problem Statement
2. **Qui se perd dans la complexité IT, et comment ?** → Segments + JTBD
3. **Pourquoi un outil local HTML est pertinent maintenant ?** → Timing + Contexte
4. **Combien de rôles/concepts/théorèmes faut-il cartographier ?** → Sizing
5. **Qu'est-ce qui répond partiellement à ce problème aujourd'hui ?** → Competitive Positioning
6. **Comment mesurer si l'outil est réellement utile ?** → Success Metrics

## Sommaire canonique

| Section | Contenu projet | Garde-fou |
|---|---|---|
| **Problem Statement** | L'IT est structurellement opaque : 54 rôles aux frontières floues, 154 concepts sans liant narratif, taxonomie DDD/DAG invisible dans les fiches de poste | "L'IT c'est compliqué" sans structure = invalide |
| **Market Segments** | (1) Soi-même — mémorisation + construction d'ontologie (2) Jeunes en orientation IT — CU1 Career Compass (3) Professionnels IT — CU2/CU3/CU4 (4) Recruteurs/LinkedIn — showcase | Segment sans JTBD = décoratif |
| **Market Opportunity** | Pas d'outil unique qui combine : taxonomie formelle + DAG + orientation métier + documentation patterns. Fenêtre : explosion des rôles spécialisés (AI Engineer, Platform Eng, etc.) | Sizing sans hypothèses = inventé |
| **Competitive Positioning** | Roadmap.sh (trop général), Backstage (trop infra), LinkedIn Skills (trop vague), aucun combine théorèmes + rôles + DAG | Différenciateur non-testable = invalide |
| **Success Metrics** | NSM = trouver le bon rôle en < 2 min · Input metrics : concepts liés au rôle cliqués / session | Métrique sans baseline = non-suivable |
| **Timeline** | outil personnel → showcase → orchestre d'agents (3 horizons) | Horizon sans trigger de révision = mort |
