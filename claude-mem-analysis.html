#CoucheAnalyse claude-mem
1 Domaine réel La context window de Claude Code = mémoire RAM volatile. Chaque session repart de zéro. Le problème est structurel : L = λW (Little) — plus le WIP cognitif croît, plus la convergence est impossible sans persistance.
2 Tension principale Volatilité vs Pertinence — capturer trop = bruit (SQLite surchargé). Capturer trop peu = perte de signal. La compression sémantique résout partiellement cette tension via Chroma (embeddings).
3 Invariant La compression préserve l'essentiel sémantique. Le résumé d'une session reste isomorphe à son contenu pour les requêtes futures — propriété de fidélité de rang (T007 Eckart-Young).
4 Morphisme interne
tool_call→ observation→ compression→ embedding→ SQLite+Chroma→ retrieval
Chaque nœud = transformation irréversible vers un espace plus abstrait.
5 Topologie DAG orienté : capture → index → serve. Pas de cycle (une session n'est pas réindexée après compression). Le graphe est acyclique par construction — compatible T016 Kahn.
6 Ker (ce qui disparaît) Le verbatim exact des échanges, le style conversationnel, les hésitations. Seul l'essentiel sémantique = observations factuelles, décisions, patterns — survit à la compression.
7 Im (ce qui est produit) Mémoire indexée : search() / timeline() / get_observations() via MCP. Injectée automatiquement dans les futures sessions via SessionStart hook.
8 Attracteur global À chaque session, le graphe de connaissance s'enrichit. Avec Graphify dessus : visualisation topologique des clusters de pensée — l'ontologie personnelle become navigable.

Décodeur narratif

Le problème qu'il résout

Chaque conversation avec Claude Code commence dans le vide. Tu expliques ton contexte, tes conventions, tes décisions — encore et encore. C'est du cognitive tax payé à chaque session. Claude sait tout ce qu'on lui dit dans la session, et rien de ce qu'on lui a dit avant.

Claude-mem est la mémoire à long terme que Claude n'a pas nativement. Il observe ce qui se passe pendant la session — chaque lecture de fichier, chaque modification de code, chaque décision — et il compresse ça en observations sémantiques persistantes.

Comment ça fonctionne en pratique

Five hooks s'accrochent au cycle de vie de Claude Code. À chaque démarrage de session, claude-mem injecte le contexte mémorisé. À chaque action d'outil, il capture une observation. À l'arrêt, il comprime tout et l'indexe.

Le résultat : quand tu reviens le lendemain sur un projet, claude-mem te redonne le contexte — "lors de la dernière session, tu travaillais sur le sprint C9, tu avais résolu un conflit CSS sur #metiers-it, et tu avais décidé de ne pas hardcoder les paths Drive".

La vision long terme : Graphify tes conversations

Claude-mem stocke tout en SQLite. Graphify peut lire ce SQLite et construire un graphe de connaissance de ta pensée : quels concepts reviennent, quels projets sont liés, quels patterns se répètent. La topologie de ton intelligence devient navigable.

C'est le Coran numérique que tu voulais faire — mais appliqué à toi-même. Ton corpus = tes conversations. L'analyse = vectorielle + graphe. La visualisation = clusters thématiques. Le but = comprendre comment tu penses pour mieux te penser.

Lien avec ton système existant

Ton auto-memory (fichiers .md dans ~/.claude/projects/.../memory/) = mémoire éditoriale, curatée à la main. Claude-mem = mémoire observationnelle, capturée automatiquement. Les deux sont complémentaires : l'un pour ce que tu veux retenir, l'autre pour ce qui s'est vraiment passé.
