### 3. **FMATHS-DOCUMENTATION-PRODUIT-PASSE1.md** 🔬 **POUR LA RIGUEUR MATHÉMATIQUE**
**Longueur** : ~6000 words | **Format** : Analyse formelle en 8 sections | **Durée de lecture** : 20-30 min

**Structure** :
1. **Ensembles** — L'ontologie minimale (DOC, AUDIENCE, PROBLEM_LEVELS, DIMENSIONS, TRANSITIONS, COHERENCE)
2. **Logique** — Les règles du jeu (règles d'existence, transformation, validité, non-contradiction)
3. **Invariants** — Le socle immuable (Intention, Traçabilité, Non-redondance, Exhaustivité)
4. **Axes de variation** — 5 axes orthogonaux (Abstraction, Business/Tech, What/How, Scope, Timeline)
5. **Analyse** — Les points de rupture (Rupture 1-4 + Dette d'intention)
6. **Catégories** — Cohérence interne (Documents de Justification vs Spécification)
7. **Topologie** — La forme globale (DAG, Entonnoir, Espaces de projection, Dimension manquante: feedback loops)
8. **Probabilités/Mesure** — Entropie informationnelle + Endomorphisme final + Indice de cohérence

**À utiliser pour** :
- Comprendre la structure profonde
- Référence formelle quand tu doutes
- Extraire les concepts clés pour ta propre documentation

### 4. **FMATHS-DOCUMENTATION-PRODUIT-PASSE2.md** 📖 **POUR LA NARRATION ORGANIQUE**
**Longueur** : ~6000 words | **Format** : Essai/podcast en 9 actes | **Durée de lecture** : 20-30 min

**Structure** (9 actes narrative) :
- **Introduction** — Le paradoxe central (4 documents, même objet, descriptions incomparables)
- **Acte 1** — Le théâtre des 4 documents (MRD, BRD, PRD, SRD) + les 3 ruptures visibles
- **Acte 2** — Les 3 socles qui ne peuvent jamais être violés (avec exemples)
- **Acte 3** — Les 5 axes de variation (où chaque document se situe)
- **Acte 4** — Les 4 points de rupture critiques (diagnostics)
- **Acte 5** — La mécanique de la cohérence (traçabilité, réduction d'ambiguïté, feedback loops)
- **Acte 6** — Les 2 rôles (Justification vs Spécification)
- **Acte 7** — La topologie secrète (entonnoir, projections, feedback boucles)
- **Acte 8** — Mesurabilité de la cohérence (4 métriques)
- **Acte 9** — Les tensions irrésolues (Détail vs Clarté, Changement vs Stabilité, etc.)
- **Coda** — Ce que tu as compris (résumé syntaxique)

**À utiliser pour** :
- Comprendre intuitivement (narration plutôt que formalisme)
- Expliquer à d'autres verbalement
- Retrouver un concept via une analogie (corps humain, symphonie, etc.)

## ⚙️ UTILISATION PRATIQUE

### Template rapide pour un nouveau projet

```
Jour 1 (3h)

Phase 0 (15 min) : MRD Charter
  → Consul ATLAS Partie 2, Phase 0 template
  → Remplis : Problem, Market, Success Metrics
  → Valide avec execs

Phase 1 (40 min) : BRD
  → Consul ATLAS Partie 2, Phase 1 template + pont vers MRD
  → Brainstorm avec stakeholders
  → Remplis : Objectives, Business Case, Phase 1 Scope
  → Valide avec PM + Execs

Phase 2 (50 min) : PRD
  → Consul ATLAS Partie 2, Phase 2 template + pont vers BRD
  → Brainstorm avec PM + UX
  → Remplis : Personas, Features, User Workflows, Acceptance Criteria
  → Valide avec PM + UX

Phase 3 (50 min) : SRD
  → Consul ATLAS Partie 2, Phase 3 template + pont vers PRD
  → Brainstorm avec Tech Lead + Architect
  → Remplis : Architecture, Tech Choices, Data Model, APIs, Non-functionals
  → Valide avec Architect

Phase 4 (10 min) : Checklist
  → Consul ATLAS Partie 4, Checklist de cohérence intégrale
  → Valide MRD↔BRD, BRD↔PRD, PRD↔SRD, Traçabilité, Non-redondance
  → Identifie gaps et résout

Jour 2 (2-3h)

Phase 5 (120+ min) : Coding avec Claude Code
  → Copie-colle le SRD complet dans Claude Code
  → Fournis le PRD aussi (pour contexte)
  → Demande d'implémenter sans questions

Résultat : Code prêt, zéro aller-retour, tout documenté.
```

- Que ton produit sera un succès commercial

### Ce système GARANTIT
- Que tu sauras WHY tu fais ce produit (MRD/BRD clair)
